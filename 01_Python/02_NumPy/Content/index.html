NumPy

Arrays that do arithmetic on a million numbers without a single loop.

4 notebooks · 1 note✍️ 6 handwritten pages

The problem behind this topic

Rahul had a million temperature readings to convert to Fahrenheit. He wrote the obvious loop.

It took eleven seconds. His colleague did the same job in 0.02 seconds with one line and no loop at all.

A Python list holds a million separate objects, each checked one at a time. The loop was not slow because of the maths — it was slow because of the bookkeeping.

A NumPy array stores those numbers as one solid block of one type. c * 9/5 + 32 then runs as compiled code across the whole block at once. That is vectorisation, and everything else in the data stack is built on it.

🔑 The one idea

A NumPy array is one typed block of memory, so operations run in compiled code, not Python loops.

The two ideas that carry everything

1. Vectorization — the expression replaces the loop.

   Python list                        NumPy array
   -----------                        -----------
   out = []
   for i in range(len(a)):            out = a + b
       out.append(a[i] + b[i])

The loop still runs, but in compiled C over packed memory instead of in the Python interpreter. Same reason one batch query beats 10,000 single-row fetches.

2. Shape is everything.

   (m, k) @ (k, n)  ->  (m, n)        the inner numbers must match
   (3, 1) +  (2,)   ->  (3, 2)        broadcasting stretches size-1 dimensions

Most NumPy bugs are shape bugs, not logic bugs. When something breaks, print .shape before you print the values.

The five gotchas the notebooks verify

Gotcha The correction
a * b looks like matrix multiplication It is element-wise. The matrix product is a @ b.
np.arange(0.1, 0.4, 0.1) should give 3 values It gives 4. Floating point. Use linspace when the count matters.
NumPy and Pandas report different standard deviations np.std is population (ddof=0); Pandas is sample (ddof=1).
np.where(...) looks like an array It is a tuple of arrays — take [0] for a 1-D input.
np.linalg.eig eigenvectors read as rows They are columns: vecs[:, i] pairs with vals[i].

NumPy Arrays — Example 01

NumPy is the library that gives Python a real array type.

A Python list can hold anything — a string next to a number next to a boolean. A NumPy array holds one type only, packed together in one block of memory.

Backend analogy: a Python list is like ArrayList<Object>. A NumPy array is like int[]. The int[] is stricter, but it is much faster and it lets you do math on the whole array in one line.

5. Data types — one type for the whole array

This is the biggest difference from a Python list. A list keeps each item's own type. An array must pick one type for everything.

If you hand it mixed types, NumPy does not throw an error. It quietly promotes everything to the one type that can hold them all. This is called upcasting.

The promotion ladder is: bool → int → float → string. The widest type in your data wins.

codecell 39
amix1 = np.asarray([True, 5, 5.0, "Kali"])
amix1
Output
array(['True', '5', '5.0', 'Kali'], dtype='<U32')

A string was in the list, so everything became a string. Look at the output: 'True', '5', '5.0' are now text in quotes. The dtype <U21 means "unicode string, up to 21 characters".

Once this happens you cannot do maths on the array any more. This is a common silent bug — one stray text value in a CSV column turns the whole column into strings.

codecell 41
amix1.dtype
Output
dtype('<U32')

Now the same idea with only booleans and numbers.

codecell 43
amix2 = np.array([True, 5])
amix2
Output
array([1, 5])

True became 1. Booleans sit at the bottom of the ladder, so integers win.

codecell 45
amix3 = np.array([False, 10])
amix3
Output
array([ 0, 10])

False became 0. Same rule.

codecell 47
amix4 = np.array([True, 'shridhar', 5, 5.0])
amix4
Output
array(['True', 'shridhar', '5', '5.0'], dtype='<U32')

A string is present again, so all four values became text — dtype='<U32'.

Choosing the type yourself

You do not have to accept NumPy's guess. Pass dtype= and it converts for you.

codecell 50
amix5 = np.asarray([False, 10], dtype=np.int32)
amix5
Output
array([ 0, 10], dtype=int32)

int32 means each number uses 32 bits. NumPy's default on most machines is int64. Choosing int32 halves the memory when you know the values are small — the same trade-off as picking int over long in Java.

codecell 52
amix6 = np.array([1, 5.55, 2, 6.9], dtype=np.float64)
amix6
Output
array([1.  , 5.55, 2.  , 6.9 ])

1 and 2 are shown as 1. and 2. — the trailing dot means they are now floats, not integers. The whole array is float64.

6. Indexing — reading one value

Give one index number per dimension. A 2-D array needs two numbers, a 3-D array needs three, and so on. Order goes outside-in: block, then row, then column.

codecell 55
# indexing a 1-D array
a1[0], a1[1], a1[-1]
Output
(np.int64(0), np.int64(1), np.int64(3))

a1[-1] is the last item. Negative numbers count backwards from the end, so you never need len(a1) - 1.

codecell 57
# indexing a 2-D array -> row first, then column
a2[1]          # whole row at index 1
Output
array([4, 5, 6])

One index on a 2-D array returns a whole row, not a single value. The row is itself a 1-D array.

codecell 59
a2[1][2], a2[1, 2]   # same element, two ways to write it
Output
(np.int64(6), np.int64(6))

Both give 6.

a2[1][2] does two steps: fetch row 1, then item 2 of that row. a2[1, 2] does it in one step. The comma form is the NumPy way — it is faster because it does not build the temporary row in between. Lists cannot do the comma form at all.

codecell 61
# indexing a 3-D array -> block first, then row, then column
a3[1]          # whole 2x2 block at index 1
Output
array([[5, 6],
       [7, 8]])
codecell 62
a3[1][0]       # row 0 inside block 1
Output
array([5, 6])
codecell 63
a3[1][0][1], a3[1, 0, 1]   # single element, two ways to write it
Output
(np.int64(6), np.int64(6))

Each index peels off one layer: block → row → value.

codecell 65
# indexing a 4-D array -> peel off one bracket layer at a time
a4[0]          # drops to 3-D: shape (1, 1, 4)
Output
array([[[   4,   44,  444, 4444]]])

a4[0][0][0], a4[0, 0, 0]      # drops to 1-D: array([4, 44, 444, 4444])

(array([   4,   44,  444, 4444]), array([   4,   44,  444, 4444]))

np.int64(444)

Four dimensions need four indexes to reach a value. Three indexes still leave you holding an array.

7. Slicing — reading many values

The pattern is array[start : stop : step].

  • start is included
  • stop is excluded
  • step is how far to jump each time

Leave any of them out and NumPy fills in a sensible default: start 0, stop end, step 1.

codecell 81
arr2
Output
array([10, 20, 30, 40, 50])
codecell 82
arr2[1:]        # from index 1 to the end
Output
array([20, 30, 40, 50])
codecell 83
arr2[:3]        # from the start up to (not including) index 3
Output
array([10, 20, 30])

arr2[:3] gives 3 items — indexes 0, 1, 2. Index 3 is left out. That "stop is excluded" rule is the one people trip on.

codecell 85
arr2[:]         # everything
Output
array([10, 20, 30, 40, 50])
codecell 86
arr2[1:4:1]     # start 1, stop 4, step 1
Output
array([20, 30, 40])
codecell 87
arr2[1:4:2]     # same window, but skip every other item
Output
array([20, 40])

Step 2 takes index 1, skips 2, takes 3. Result: [20, 40].

codecell 89
arr2[:4:3]      # start 0, stop 4, step 3
Output
array([10, 40])

Takes index 0, jumps 3, takes index 3. Result: [10, 40].

codecell 91
arr2[::4]       # whole array, step 4
Output
array([10, 50])
codecell 92
arr2[::]        # same as arr2[:]
Output
array([10, 20, 30, 40, 50])

arr2[::4] takes index 0 and index 4 → [10, 50].

One important difference from lists: a NumPy slice is a view, not a copy. Change the slice and you change the original array. A Python list slice gives you a fresh copy. Use .copy() when you really want a separate array.

13. Changing an array in place

Everything above returned a copy. These two actually modify the array.

First, plain assignment to an index.

codecell 128
arr2[0] = 100
arr2
Output
array([100,  20,  30,  40,  50])

arr2 really changed. Note the type rule still applies — assign "hello" into an integer array and you get an error, because the array's dtype is locked in.

Second, the .sort() method (not the np.sort() function).

codecell 131
arr2.sort()
codecell 132
arr2
Output
array([ 20,  30,  40,  50, 100])

Two things to notice:

  1. arr2.sort() printed nothing — it returns None, like list.sort().
  2. arr2 itself is now sorted.

So: np.sort(a) gives a sorted copy, a.sort() sorts in place. Mixing them up (a = a.sort()) is a classic bug — it sets a to None.

14. Appending

np.append() looks like list.append() but behaves completely differently.

codecell 135
np.append(arr2, 1000)
Output
array([  20,   30,   40,   50,  100, 1000])
codecell 136
arr2      # not appended
Output
array([ 20,  30,  40,  50, 100])

The value was added in the returned array, but arr2 is unchanged. Again — you must assign the result.

And the method version simply does not exist.

codecell 138
arr2.append(1000)
Output
---------------------------------------------------------------------------
AttributeError                            Traceback (most recent call last)
Cell In[77], line 1
----> 1 arr2.append(1000)

AttributeError: 'numpy.ndarray' object has no attribute 'append'

AttributeError: 'numpy.ndarray' object has no attribute 'append'.

This is not an oversight. A list can append cheaply because it keeps spare room at the end. A NumPy array is one tight block of memory with no spare room, so every "append" has to allocate a whole new block and copy everything across. NumPy makes that cost visible by refusing to offer the method.

If you need to build up data item by item, use a Python list and convert once at the end with np.array(my_list).

The pattern worth memorising: almost every np.something(array) function returns a copy. If you forget to assign the result, your change disappears. The only in-place operations here are direct assignment (a[0] = 100) and the .sort() method.

Three mistakes to avoid

  1. One string in the data turns the whole array into strings — check .dtype when maths silently stops working.
  2. stop in a slice is excluded. a[:3] gives 3 items, not 4.

4. shape and reshape — the same data, a different grid

shape is a tuple giving the length of each dimension. a = np.arange(6) gives 6 values and a.shape is (6,). The trailing comma is Python's way of writing a one-item tuple — it is not a typo, and it is not a second empty dimension.

reshape lays those same 6 values out on a different grid:

        a = [0 1 2 3 4 5]        shape (6,)      6 values

        reshape(2,3)             reshape(3,2)            reshape(1,6)
        [[0 1 2]                 [[0 1]                  [[0 1 2 3 4 5]]
         [3 4 5]]                 [2 3]
                                  [4 5]]
        2 x 3 = 6  OK            3 x 2 = 6  OK           1 x 6 = 6  OK

The one rule

The product of the new shape must equal the number of elements. That is why the last line is commented out:

a.reshape(1,4)
# ValueError: cannot reshape array of size 6 into shape (1,4)

1 x 4 = 4, but the array has 6 values. NumPy will not invent two values and will not drop two. The error saved under that cell is real — it came from running the line before it was commented out. Keep it; a remembered error message is worth more than a rule.

Two things worth knowing now

Point Detail
reshape does not change a It returns a new view. a is still (6,) after all three calls — which is why the second and third reshape calls still work.
A view shares memory Verified: b = a.reshape(2,3), then b[0,0] = 99, and a[0] is now 99. No copy was made. Use .copy() when you need independence.
-1 means "you work it out" a.reshape(-1, 2) gives the same 3x2 result. Useful when the row count depends on data you have not counted.

Takeaway: shape is the grid, reshape redraws the grid, and the number of values never changes. When a NumPy error confuses you, print .shape first — most NumPy bugs are shape bugs.

7. Comparisons — the boolean mask

A comparison is arithmetic too. It runs on every element and returns an array of True and False, the same shape as the input.

   a        =  [10   20    30  ]
   a > 15   ->  [False True True]
Cell line Meaning Result
a > 15 which values are above 15? [False True True]
a == 20 which equal 20? [False True False]
a != 20 which are not 20? [True False True]
a <= 20 which are 20 or less? [True True False]

That result array is called a mask, and it is the point of the whole exercise. A mask is not usually printed — it is fed straight back into the array:

a[a > 15]        # -> [20 30]     keep the values that passed
a[a > 15] = 0    #                overwrite only those values
(a > 15).sum()   # -> 2           True counts as 1, so sum = how many passed
Note

💡 Engineering Extension — Recommended Extension - Not part of instructor curriculum.

a[a > 15] is a WHERE clause. You describe the condition and NumPy applies it to the whole column at once — no cursor, no row loop. Pandas' df[df.age > 30] is exactly this same mechanism, one layer up.

The one real trap

Use &, |, ~ for combining conditions — not and, or, not:

a[(a > 15) & (a < 30)]     # correct
a[a > 15 and a < 30]       # ValueError: truth value of an array is ambiguous

Python's and wants one true-or-false answer. An array of three booleans cannot give one. Also keep the brackets: & binds tighter than >.

Takeaway: a comparison gives you a mask, and a mask is how you filter, count, and update parts of an array without a loop.

8. Broadcasting — when shapes do not match

Section 6 needed matching shapes. Broadcasting is the set of rules that lets NumPy work with mismatched shapes by stretching the smaller one, without copying it.

Cell line Shapes Result What was stretched
a + 10 (3,) + scalar [11 12 13] 10 acts as [10 10 10]
a * 5 (3,) + scalar [5 10 15] same idea
a + [10,20,30] (3,) + (3,) [11 22 33] nothing — the list is just converted to an array
[[1],[2],[3]] + [10,20] (3,1) + (2,) a 3x2 matrix both were stretched

The last one, drawn out

This is the cell worth understanding. A column of 3 plus a row of 2 gives a 3x2 grid — every pairing.

   column (3,1)          row (2,)              result (3,2)
                         [10  20]
      [1]                                      [11  21]      1+10  1+20
      [2]        +                    =        [12  22]      2+10  2+20
      [3]                                      [13  23]      3+10  3+20

   the column is copied across 2 columns
   the row    is copied down   3 rows      (conceptually — no memory is actually copied)

The rule

Line the shapes up from the right. Each pair of dimensions must be either equal, or one of them must be 1.

   (3,1)                (3,)
   (  2)                (4,)
   -----                -----
   3 vs nothing -> 3    3 vs 4 -> neither equal nor 1
   1 vs 2       -> 2                 ValueError: operands could not be broadcast
   = (3,2)  OK

Where you will actually use this

Centring a dataset. X is (1000, 5) — 1000 samples, 5 features. X.mean(axis=0) is (5,) — one mean per feature.

X_centered = X - X.mean(axis=0)      # (1000,5) - (5,) -> (1000,5)

One row of 5 means is applied to all 1000 rows. That is feature scaling, and it is one line because of broadcasting.

Takeaway: broadcasting stretches size-1 (or missing) dimensions so shapes fit. It is what makes "subtract the mean from every row" a single expression — but it will also silently build a huge matrix if you mix up a row and a column, so check the result shape.

10. arange and linspace — building sequences

Both make evenly spaced numbers. They differ in which part you control.

Call Result You control
np.arange(1,10) [1 2 ... 9] the step (default 1)
np.arange(1,10,2) [1 3 5 7 9] step of 2

np.linspace(10,20,4) [10. 13.33 16.67 20.] 4 values, spacing worked out for you

The endpoint rule — they disagree, and it matters

   np.arange(1,10)      ->  1 ... 9      stop is EXCLUDED   (like range())
   np.linspace(0,1,5)   ->  0.0 ... 1.0  stop is INCLUDED   (both ends kept)

arange follows Python's range. linspace is built for plotting and sampling, where you want both ends of the interval.

Choosing between them

   Do I care about the gap between values?   ->  arange
   Do I care how many values I get?          ->  linspace

The floating-point trap

Never use arange with a decimal step when the count matters:

np.arange(0.1, 0.4, 0.1)     # -> [0.1 0.2 0.3 0.4]   FOUR values, not three

Verified. 0.1 cannot be stored exactly in binary, the accumulated error lands just under 0.4, and one extra value slips in. np.linspace(0.1, 0.4, 4) asks for a count and cannot do this. Integers: arange. Decimals: linspace.

Takeaway: arange for a known step, linspace for a known count. arange excludes the stop; linspace includes it.

The trap that will bite you later

np.std divides by n. Pandas divides by n-1. Same data, different answer:

   np.std([10,20,30,40])              ->  11.1803...     ddof=0, population
   pd.Series([10,20,30,40]).std()     ->  12.9099...     ddof=1, sample

Both verified above. NumPy assumes your array is the whole population. Pandas assumes it is a sample of something bigger, and corrects for it. Neither is wrong; they answer different questions. When two tools report different standard deviations for the same column, this is why. Force it with np.std(arr, ddof=1).

14. The dot product — the most important operation in ML

np.dot(a, b)    # -> 32
a @ b           # -> 32   identical

Multiply matching positions, then add everything up. Two arrays go in, one number comes out:

   a = [1  2  3]
   b = [4  5  6]
        |  |  |
        v  v  v
        4 +10 +18   =  32

@ is the operator form, added to Python for exactly this. Prefer it — a @ b reads better than np.dot(a, b) once expressions get longer.

Why this one operation matters

A dot product is a weighted sum, and a weighted sum is what almost every model computes:

features = np.array([1200, 3, 15])          # size, bedrooms, age
weights  = np.array([  85, 12000, -400])    # learned from data

price = features @ weights                  # 1200*85 + 3*12000 + 15*-400

That single expression is linear regression's prediction. It is also one neuron in a neural network. Change the numbers and the meaning changes; the operation does not.

The other common use is similarity. The cosine similarity behind semantic search and RAG retrieval is a dot product of two normalised vectors.

Takeaway: the dot product turns two vectors into one number by multiplying and adding. Learn to read @ as "weighted sum" and a lot of ML code becomes readable.

15. Matrix multiplication — many dot products at once

Same operator, two dimensions. np.matmul(a, b) and a @ b give the same result.

   a = [[1 2]        b = [[5 6]        a @ b = [[19 22]
        [3 4]]             [7 8]]               [43 50]]

Every output cell is one dot product: row i of a with column j of b.

   result[0,0] = row0 . col0 = 1*5 + 2*7 = 19
   result[0,1] = row0 . col1 = 1*6 + 2*8 = 22
   result[1,0] = row1 . col0 = 3*5 + 4*7 = 43
   result[1,1] = row1 . col1 = 3*6 + 4*8 = 50

The shape rule

   (m, k) @ (k, n)  ->  (m, n)
        ^     ^
        the inner numbers must match, and they vanish

(2,3) @ (3,4) gives (2,4). (2,3) @ (2,3) is an error. When a matrix error appears, print both shapes and line them up — the inner pair is nearly always the problem.

dot vs matmul vs *

Expression On 2-D arrays
a * b element-wise — position by position, not a matrix product
np.dot(a,b) matrix product
a @ b matrix product

np.dot and @ agree for 1-D and 2-D (verified). They differ beyond that: for 3-D+ arrays @ treats the leading dimensions as a batch of matrices, which is what you want for batched data, while np.dot does something else. np.dot(3,4) also happily returns 12, while 3 @ 4 raises an error — @ refuses scalars on purpose.

Use @. It is clearer and its stacked behaviour is the one that scales.

Where it shows up

One row of features @ weights gives one prediction. A whole matrix of 1000 samples @ the same weights gives 1000 predictions in one call — no loop over rows. That is a forward pass.

Takeaway: matrix multiplication is a grid of dot products. Watch the inner dimensions, and use @.

np.sort(arr) [10 20 30 40] the values, sorted
np.argsort(arr) [1 3 2 0] the positions that would sort it
np.where(arr==30) (array([2]),) positions where the condition is True
np.searchsorted(np.sort(arr),25) 2 where 25 would go to keep order

argsort — read the answer carefully

[1 3 2 0] is not data. It is instructions: "take index 1 first, then 3, then 2, then 0." Follow it: arr[1]=10, arr[3]=20, arr[2]=30, arr[0]=40 — sorted.

Why bother? Because it sorts other things by this array:

order = np.argsort(scores)
names[order]              # names, ordered by score
names[np.argsort(scores)[::-1]][:3]      # top 3

Sorting one array by another array is the everyday use. Pandas' sort_values is this, underneath.

np.where returns a tuple

Note the shape of the output: (array([2]),) — a tuple holding one array, not a bare array. There is one array per dimension, so a 2-D array gives you (rows, cols). To get the plain indices from a 1-D array, take [0]:

np.where(arr == 30)[0]     # -> array([2])

Forgetting the [0] is a normal first mistake.

searchsorted needs sorted input

It runs a binary search, so it is only correct on a sorted array — hence the np.sort(arr) inside the call. It answers "at which index does 25 belong?" Answer: 2, between 20 and 30. This is how you bucket values into bins or ranges without a loop.

Takeaway: sort gives values, argsort gives positions. Reach for argsort when the array you are sorting by is not the array you want back.

Two things to notice

The double brackets. np.vstack((a,b)) — the arrays go in as one tuple argument, not as two arguments. np.vstack(a, b) is an error. The same applies to hstack and concatenate.

The split rule

np.split demands an equal division:

np.split(np.array([1,2,3,4,5]), 3)
# ValueError: array split does not result in an equal division

18. Linear algebra — np.linalg

Three operations on A = [[1,2],[3,4]]. This is the module that connects NumPy to the maths behind ML.

Call Result Meaning
np.linalg.inv(A) [[-2. 1.] [1.5 -0.5]] the inverse — the matrix that undoes A
np.linalg.det(A) -2.0000000000000004 the determinant — a single number describing the matrix
np.linalg.eig(A) values [-0.372, 5.372] + vectors the eigendecomposition

The inverse

inv(A) is the matrix version of 1/x. The check is the identity matrix from section 9:

A @ np.linalg.inv(A)     # -> [[1. 0.] [0. 1.]]     verified

If a matrix multiplication is the operation, the inverse is the undo.

The determinant, and why it is -2.0000000000000004

That trailing ...04 is not a NumPy bug — it is binary floating point. The true answer is -2, computed through divisions that cannot be represented exactly. Never compare floats with ==; use np.isclose(det, -2).

The determinant also tells you whether the inverse exists at all:

   det != 0   ->  invertible
   det == 0   ->  singular, no inverse

Verified: np.linalg.inv([[1,2],[2,4]]) raises LinAlgError: Singular matrix. The second row there is just the first row doubled — it carries no new information. In data terms, that is a perfectly correlated feature, and it is the same reason multicollinearity breaks linear regression.

Note

💡 Engineering Extension — Recommended Extension - Not part of instructor curriculum.

To solve Ax = b, use np.linalg.solve(A, b) rather than inv(A) @ b. It is faster and numerically more stable. Computing an explicit inverse is usually a sign you are doing more work than the problem needs.

Eigenvalues and eigenvectors

An eigenvector is a direction that A does not rotate — it only stretches it. The eigenvalue is the stretch factor.

   A @ v  =  lambda * v

Verified for the first pair: A @ vecs[:,0] and vals[0] * vecs[:,0] both give [0.30697009, -0.21062466].

Read the eigenvectors as columns, not rows. vecs[:, 0] goes with vals[0]. Taking vecs[0] — the first row — is the standard mistake here and it silently gives you nonsense.

This is the machinery under PCA: the eigenvector with the largest eigenvalue is the direction in which your data varies most, and that becomes the first principal component.

Takeaway: np.linalg is where the maths lives. det == 0 means no inverse, floats never compare exactly, and eigenvectors are columns.

Goal: get to a matrix we can trust, and make a defensible decision about each of the two problems.

Cause monitoring agent restarted a real production incident
